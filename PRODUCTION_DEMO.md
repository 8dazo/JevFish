# JevFish production-demo runbook

This runbook describes the intentionally small production shape used for a public demo. It is not the final horizontally scalable architecture.

## Deployment shape

```text
browser
  |
  v
single JevFish web service
  |- bundled Vue frontend
  |- Flask API behind Gunicorn
  |- OASIS simulation subprocesses
  |- persistent /app/backend/uploads
  |
  +--> TypeSafe Jev
  +--> OpenAI-compatible System Two provider
  +--> Zep Cloud
```

The demo uses **one Gunicorn worker** on purpose. `SimulationRunner` owns live subprocess/state in the web process. Multiple web workers or multiple service replicas would split that ownership and are not supported by this demo architecture.

## Required production environment

```env
APP_ENV=production
FLASK_DEBUG=false
SECRET_KEY=<at least 32 random characters>

TYPESAFE_API_KEY=...
TYPESAFE_DEFAULT_MODEL=jev-latest

LLM_API_KEY=...
LLM_BASE_URL=...
LLM_MODEL_NAME=...

ZEP_API_KEY=...

JEVFISH_DECISION_ENGINE=hybrid
JEVFISH_OBSERVATION_MODE=oasis_refresh
JEVFISH_SAMPLE_PROBABILITIES=false

MAX_CONCURRENT_SIMULATIONS=2
DEMO_STARTS_PER_MINUTE=4
DEMO_MUTATIONS_PER_MINUTE=20
GUNICORN_THREADS=8
GUNICORN_TIMEOUT=600
```

Do not commit real keys. Configure them in the deployment provider's secret/environment UI.

## Persistence

Mount persistent storage at:

```text
/app/backend/uploads
```

This preserves simulation configuration, SQLite databases, run state, metrics, uploads, and generated artifacts across service restarts.

The included `render.yaml` provisions a 10 GB persistent disk at this path.

## Health endpoints

Liveness:

```text
GET /healthz
```

Readiness:

```text
GET /readyz
```

Readiness checks that required credentials exist and that simulation storage is writable. It deliberately does not make paid external API calls.

Safe public runtime status:

```text
GET /api/system/status
```

Per-simulation Jev routing metrics:

```text
GET /api/system/simulations/<simulation_id>/metrics
```

The UI polls these metrics during an active simulation and displays the System-One/System-Two routing split.

## Render

The repository includes a `render.yaml` Blueprint for a single Docker web service with persistent storage.

Before the first deploy, provide these secret values in Render:

- `TYPESAFE_API_KEY`
- `LLM_API_KEY`
- `LLM_BASE_URL`
- `LLM_MODEL_NAME`
- `ZEP_API_KEY`

`SECRET_KEY` is generated by the Blueprint.

After deployment, verify:

```bash
curl -f https://<service>/healthz
curl -f https://<service>/readyz
curl -f https://<service>/api/system/status
```

Then open the root URL and use **Try sample simulation**. The bundled sample is fictional and requires no user upload.

## Failure behavior

- If provider credentials are missing, production startup fails validation rather than starting half-configured.
- If the backend restarts during a simulation, stale persisted `running` state is marked `failed/interrupted`; the UI will not remain stuck forever.
- The public demo rejects new simulation starts when its configured concurrency capacity is full.
- Expensive mutation routes use a small per-IP sliding-window rate limit to reduce accidental API-credit exhaustion.

## CI release gate

`.github/workflows/production-demo.yml` must pass before release. It:

1. compiles the production Python entrypoints and live-metrics adapter;
2. builds the Vue frontend;
3. builds the complete production Docker image;
4. boots that image with non-secret CI placeholders;
5. probes `/healthz`, `/readyz`, `/api/system/status`, and a Vue history-mode deep link.

The existing JevFish unit tests and frontend build workflow remain separate gates.

## What this demo is not

This deployment is intentionally **not** multi-instance. Before horizontal scaling, move live simulation ownership into a durable job queue/worker system and move mutable simulation state into shared storage. Redis/Celery/Kubernetes are therefore not prerequisites for the public demo.
